## 2024-04-27 - [HIGH] Fix command injection risk in Process.Start
**Vulnerability:** Command injection risk and arbitrary file/program execution via `Process.Start` when `UseShellExecute = true` is used with user-provided input. In `MainForm.cs`, a user-provided directory path was directly passed to `Process.Start` with `UseShellExecute = true`, and a URL from a LinkLabel was passed without scheme validation.
**Learning:** `Process.Start` with `UseShellExecute = true` passes the input to the OS shell, which can interpret it as a command or executable instead of just a path or URL if maliciously crafted. Using `UseShellExecute = false` directly invokes the specified executable.
**Prevention:** For opening directories, use `explorer.exe` explicitly with `UseShellExecute = false` and properly quote the normalized path (remember to trim trailing backslashes so the quote isn't escaped). For URLs, strictly validate the scheme (`Uri.TryCreate` checking for `http` or `https`) before passing it to `Process.Start`.
