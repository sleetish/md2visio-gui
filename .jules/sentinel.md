## 2024-05-08 - [Path Traversal via Cross-Platform Filename Extraction]
**Vulnerability:** The application was vulnerable to path traversal because it relied solely on `Path.GetFileName()` or `Path.GetFileNameWithoutExtension()` to extract filenames from user-provided paths. On Windows systems running in cross-platform environments (or when processing paths from other OSs), providing a path with forward slashes (e.g., `../../../etc/passwd` or `some/dir/file.vsdx`) bypasses `Path.GetFileName()` if it only expects backslashes (or vice versa), allowing the directory traversal payload to be injected directly into the output path.
**Learning:** `System.IO.Path.GetFileName` is OS-dependent and does not automatically normalize or handle mixed slashes correctly when analyzing paths originating from different platforms. Simply passing an untrusted path to this function is insufficient for sanitization.
**Prevention:** Always normalize slashes in untrusted paths to `Path.DirectorySeparatorChar` (e.g., `.Replace('/', Path.DirectorySeparatorChar).Replace('\\', Path.DirectorySeparatorChar)`) *before* invoking `Path.GetFileName()` or `Path.GetFileNameWithoutExtension()`. Additionally, always check if the resulting filename is empty, and provide a safe default string (e.g., `"output"`) to ensure deterministic behavior.
