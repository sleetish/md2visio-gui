## 2024-05-23 - Command Injection via Process.Start
**Vulnerability:** Using `Process.Start` with `UseShellExecute = true` on user-controlled inputs (like URLs or directory paths) can lead to command injection or arbitrary file execution if the input is malicious.
**Learning:** Even opening a file explorer or a browser requires strict input validation because the underlying shell executes the path string as a command. A backslash at the end of a path can escape the closing quote in arguments.
**Prevention:** Mitigate shell execution by validating URL schemes via `Uri.TryCreate` (allowing only http/https). For opening local directories, verify existence via `Directory.Exists`, normalize the path with `Path.GetFullPath`, and use `explorer.exe` with `UseShellExecute = false`. Specifically, when calling `explorer.exe` with `UseShellExecute = false`, trim trailing backslashes from the path before enclosing it in double quotes in the `Arguments` property to prevent the backslash from escaping the closing quote.
