## 2025-04-29 - Secure URL Validation and Local Directory Launching
**Vulnerability:** The application used `Process.Start(new ProcessStartInfo(url) { UseShellExecute = true });` directly from an unvalidated UI link, risking command execution or opening arbitrary file handlers via schemes like `file://` or `javascript:`. Similarly, opening a directory relied on raw UI input directly into the `FileName` property with `Verb = "open"`, creating a command execution risk.
**Learning:** Always explicitly validate expected schemas (e.g., HTTP/HTTPS) for remote links before launching. For local directories, explicitly invoke `explorer.exe` with `UseShellExecute = false`, properly normalize/sanitize the directory path to eliminate path traversal, strip trailing directory separators that might escape closing quotes, and enclose the path securely within arguments.
**Prevention:** Avoid passing raw user input directly to `Process.Start`. Apply schema whitelisting for URIs (`Uri.TryCreate` with `UriSchemeHttp`/`UriSchemeHttps`), and enforce strict executable/argument separation (`FileName` vs `Arguments`) while disabling `UseShellExecute` for local OS paths.
